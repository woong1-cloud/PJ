# 런칭 참여자 1단계 — 명단

2026-09-07. 아이데이션: `2026-09-07-launch-participants-design.md`

**권한은 안 건드린다.** 전체 관리자만 런칭을 보는 지금 상태 그대로, 명단만
만든다. 위험이 0인데도 두 가지가 바로 생긴다 — 담당자 후보 좁히기와
메일 받을 사람.

권한을 여는 것은 3단계다. 그 앞에 라우트 보안 점검이 있다(2단계, 완료).

**참관은 안 만들기로 했다 (2026-09-07).** 처음엔 `참여자/참관` 을 고르게
했는데, 런칭에 들어오는 사람은 대개 일을 할 사람이고 경영자는 보고로
받는다 — 보고 화면은 따로 고민한다. 라디오와 토글을 뺐다.

---

## 1. 데이터

`launch_members` 는 `0031_launch.sql` 에 이미 있다. 지금 0건. 두 가지를 고친다.

```sql
-- PK 를 넓힌다. 한 사람이 한 런칭에서 두 역할을 가질 수 있다.
--   (launch_id, member_id) → (launch_id, member_id, role_name)
-- 0건인 지금이 공짜다. 데이터가 들어간 뒤엔 살아있는 테이블에 걸어야 한다.
--
-- role_name 이 PK 에 들어가므로 not null 이어야 한다. 역할 없이 넣는 일은
-- 없다 — 역할이 곧 그 사람이 무엇을 보는가다.

-- 누가 넣었는지 남긴다. 명단에 넣는 것이 유일한 통제 지점이라
-- 그 결정에 이름이 붙어야 한다. created_at 은 이미 있다.
alter table launch_members add column created_by uuid references team_members(id);
```

`can_edit boolean not null default true` 는 그대로 쓴다 — 1단계에서는 저장만
하고 아무 데도 안 쓴다. 3·4단계에서 문을 가르는 값이다.

## 2. 라우트

전부 `requireGlobalAdmin()`. **1단계에서는 권한을 안 연다.**

| | |
|---|---|
| `GET /api/launch/[id]/members` | 명단. 팀원 이름·소속을 붙여 준다 |
| `POST /api/launch/[id]/members` | 여럿 한 번에 넣는다 — `{ memberIds: [], roleName, canEdit }` |
| `DELETE /api/launch/[id]/members` | 한 줄 빼기 — `{ memberId, roleName }` |

**POST 가 배열을 받는 이유.** 역할 줄에서 3명을 체크해 한 번에 넣는다.
한 명씩 4번 왕복하면 중간에 하나가 실패했을 때 무엇이 들어갔는지 모른다.

**DELETE 가 `role_name` 을 받는 이유.** PK 가 셋이 되어서다. 한 사람이
재무팀이면서 법무팀일 수 있으므로 `memberId` 만으로는 어느 줄인지 못 짚는다.

**이미 있는 (런칭·사람·역할) 조합은 조용히 넘긴다**(`on conflict do nothing`).
3명을 넣는데 하나가 이미 있다고 통째로 실패하면 안 된다. 결과에 몇 건이
실제로 들어갔는지 준다.

## 3. 세는 것 — `lib/launchMembers.js`

화면이 직접 세지 않는다. 순수 함수로 빼서 테스트한다.

```js
// 역할 줄 하나 = { role, members, ownerCount, supportCount, assignedCount }
export function memberRows({ tasks, members })
```

- `role` — 항목에서 뽑은 주관·지원 역할 전부(`splitRoles` 규칙 그대로)
- `members` — 그 역할로 들어온 사람들
- `ownerCount` / `supportCount` — 그 역할이 주관·지원인 항목 수
- `assignedCount` — 그중 담당자가 붙은 수

**정렬은 주관 건수 많은 순.** 역할 띠와 같은 규칙이다 — 숫자가 보이는
목록은 그 숫자로 정렬돼 있어야 눈이 한 번만 훑는다.

**사람이 없는 역할도 줄로 남긴다.** 빈 줄이 곧 "여기 아무도 없다"는
말이다 — 그게 이 화면을 보는 이유다.

**명단에 있는데 항목에 없는 역할**도 줄로 남긴다. 역할 이름을 잘못 골랐다는
뜻이라 보여야 고쳐진다.

## 4. 화면

**탭이 아니라 제목 줄 단추다.**

처음에 탭으로 만들었다가 옮겼다. 탭 줄의 넷(보드·결정 대기·주간 진척·간트)은
**전부 같은 471건을 다르게 비추는 렌즈**인데, 명단은 471건을 비추지 않는다 —
이 런칭의 설정이다. 제목 줄이 이미 그런 것들을 들고 있다(전제·내보내기·⋯).

> **제목 줄은 이 런칭에 대한 것, 탭 줄은 471건에 대한 것.**

`⋯` 안에 숨기지 않는다. 지금 0명인데 숨기면 아무도 안 열어 본다 — 건수가
곧 신호라 없을 때는 점선 `참여자 없음` 으로 뜬다.

누르면 넓은 창(`sm:max-w-3xl`, 768px)이 열린다. 15줄 표를 512px 에 넣으면
답답하고, 아래로 펼치는 판(전제 방식)으로 하면 15줄이 보드를 통째로 밀어낸다.

```
참여자 — 호카                                  19명 중 5명 · [＋ 넣기]

역할                    사람                          주관   지원   담당자
브랜드PM                한지웅 ✕                       108     20      0
브랜드                  (아직 없음)  [＋]              100      9      0
개발PM                  (아직 없음)  [＋]               89     18      0
CAIO실                  변기석 ✕  장재혁 ✕                37     75      0
재무팀                  황경임 ✕  정소희 ✕             17     24      0
…
전체                    ─                               8      0      —
```

**맨 오른쪽 `담당자` 칸이 이 화면의 요점이다.** "역할은 정했는데 아직 아무도
안 집은 것"을 드러낸다. 지금 전부 0이다.

**`can_edit` 컬럼은 남기되 화면에서 뺐다.** 화면에 남기면 거짓말이 된다 —
참관으로 넣었는데 고칠 수 있으면. 컬럼은 보고 화면을 만들 때 다시 쓸
자리이고, 지우는 마이그레이션은 되돌리기 어렵다. 값은 전부 참으로 들어간다.

### 넣기 — 창이 아니라 줄이 펼쳐진다

창 안의 창은 겹침이 까다롭고, 무엇보다 뒤의 역할 줄이 가려져 **어디에 넣는
중인지를 놓친다.** 역할 줄의 `[＋]` 를 누르면 그 자리에서 아래로 펼쳐진다.

```
재무팀   황경임 ✕  정소희 ✕  [닫기]                 16   24   0/16
  ┌──────────────────────────────────────────────────────┐
  │ ☑ 이수진 (재무)   ☐ 김동현 (스파오)  ☐ 박천주 (스파오) │
  │ ☐ 이보담 (재무)   ☐ 안수아 (스파오)  ☐ 윤다혜 (스파오) │
  │ ⚠ 471건 전부를 보게 됩니다 · 엑셀 내보내기는 안 됩니다  │
  │                            [그만두기]  [1명 넣기]      │
  └──────────────────────────────────────────────────────┘
```

- **활성 팀원만** 후보에 올린다(`is_active`)
- **이미 그 역할로 들어온 사람은 목록에서 뺀다** — 체크해도 아무 일이 안
  일어나는 줄을 두지 않는다
- 소속을 이름 옆에 쓴다. 동명이인과 "재무 조직 사람" 찾기를 같이 돕는다
- **경고 문구는 1단계에도 넣는다.** 아직 권한이 안 열려 실제로는 못 보지만,
  이 문구를 나중에 붙이면 이미 20명이 들어간 뒤가 된다

## 5. 담당자 후보 좁히기 (1b)

명단이 생기면 항목 창의 담당자 칸을 바꾼다.

지금은 `assignee_name` 자유 글자 칸이고 **501건 중 0건**이 채워져 있다.
이것을 **그 항목의 주관 역할로 들어온 참여자** 중에서 고르게 한다.

- 후보가 있으면 드롭다운. 19명이 아니라 2~3명이다
- 후보가 없으면(그 역할에 아무도 없으면) 지금처럼 자유 글자
- 고르면 `assignee`(계정 uuid)에 넣는다 — **메일 주소가 따라온다**
- 자유 글자로 쓰면 `assignee_name` 에 남는다(계정 없는 사람)
- 화면은 `assignee?.name ?? assignee_name` 으로 보여준다

두 칸 다 이미 있어 마이그레이션이 없다.

## 6. 안 하는 것

- **권한을 안 연다.** 참여자는 아직 런칭을 못 본다
- **메일을 안 보낸다.** 명단만 만든다
- **추천 기능을 안 만든다.** 참여자가 못 들어오는 단계라 추천할 사람이 없다
- **명단 복사를 안 만든다.** 런칭이 하나뿐이다

## 7. 마치면 확인할 것

- 제목 줄 `참여자` 단추를 누르면 창이 뜨고 역할 15줄과 주관 건수가 나온다
- 아무도 없을 때 단추가 점선 `참여자 없음` 으로 뜬다
- 재무팀 줄의 `＋` 를 누르면 그 줄 아래가 펼쳐진다 (창이 또 뜨지 않는다)
- 3명을 한 번에 넣고 한 명을 빼기
- 한 사람을 두 역할에 넣기 (PK 를 넓힌 이유)
- 이미 넣은 사람이 후보에서 빠지고, 다른 역할 후보에는 남는다
- 항목 고치기의 담당자 칸이 그 역할 사람만 보여줌
- 담당자를 붙이면 창의 `담당자` 칸이 `0/16` → `1/16` 으로 오름
