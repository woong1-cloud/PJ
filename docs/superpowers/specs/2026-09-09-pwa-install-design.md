# PWA 1단계 — 설치되는 것까지

2026-09-09. 협조 요청 배포 뒤.

---

## 0. 이번에 무엇을 하나

**폰 홈 화면에 깔리는 것까지만 한다.** 푸시도, 캐싱도, QR 도 안 한다.

이유는 순서다. 지금 **폰에서 이 앱이 어떤지 아무도 모른다.** 반응형 분기가
147개 있지만 화면 규모에 비해 얇고, 간트는 최소 가로폭이 720px 이라 폰에서
옆으로 밀어야 한다. 런칭 보드는 1398줄짜리 화면이다.

껍데기를 먼저 만들면 **그것이 모바일을 재는 도구가 된다.** 본인 폰에 깔고
실제로 써 보면 무엇을 고쳐야 하는지가 추측이 아니라 목록으로 나온다.
그 목록이 나오기 전에 푸시를 달거나 사람들에게 QR 을 돌리면, 한 번 열어 보고
지운다. **그러면 푸시도 같이 죽는다** — 알림 권한은 한 번 거절당하면 그 사람은
영영 못 받는다.

## 1. 범위

| 하는 것 | 안 하는 것 |
|---|---|
| 매니페스트 · 아이콘 | 오프라인 캐싱 |
| 최소 서비스워커 | 푸시 알림 |
| 미들웨어 한 줄 | PC 의 QR 팝업 |
| iOS 용 메타 태그 | 설치 유도 배너 |
| 매처를 지키는 테스트 | 모바일 화면 고치기 |

**설치 유도도 안 한다.** 이번 사용자는 한 사람이다 — 본인이 직접 깐다.
남에게 권하는 것은 폰에서 쓸 만해진 뒤의 일이다.

## 2. 조용히 깨지는 자리 — 미들웨어 한 줄

**이것을 모르면 하루를 날린다.** 지금 매처는 이렇다:

```js
matcher: ['/((?!_next/static|_next/image|favicon.ico|api).*)']
```

`/manifest.json` 도 `/sw.js` 도 여기 안 걸러진다. 그래서 **비로그인 상태로 그
둘을 요청하면 `/login` 으로 307 된다.** 매니페스트는 HTML 이 되어 무효가 되고,
서비스워커는 콘텐츠 타입이 안 맞아 **등록 자체가 실패한다.**

로그인한 뒤에는 쿠키가 붙어 통과한다. 그래서 더 나쁘다 — **본인 브라우저에서는
멀쩡해 보이고, 처음 들어온 사람의 로그인 화면에서만 안 된다.** 설치를 권하고
싶은 자리가 정확히 거기다.

고칠 것:

```js
matcher: ['/((?!_next/static|_next/image|favicon.ico|api|manifest\\.json|sw\\.js|icons/).*)']
```

## 3. 매니페스트 — `public/manifest.json`

`app/manifest.js` 라는 Next 의 길도 있지만 **정적 파일로 둔다.** 빌드 산출물이
아니라 그냥 파일이라 `output: 'standalone'` 에서 어떻게 나올지 고민할 것이
없고, 미들웨어 제외 목록에 **파일 이름 그대로** 적을 수 있다.

```json
{
  "name": "모아 MOA",
  "short_name": "모아",
  "description": "요구사항과 프로젝트를 한곳에 모읍니다.",
  "start_url": "/launch",
  "scope": "/",
  "display": "standalone",
  "background_color": "#ffffff",
  "theme_color": "#4f46e5",
  "lang": "ko",
  "icons": [
    { "src": "/icons/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icons/icon-512.png", "sizes": "512x512", "type": "image/png" },
    { "src": "/icons/icon-512-maskable.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ]
}
```

**`start_url` 을 `/` 로 두지 않는다.** 루트는 미들웨어가 무조건 `/login` 으로
보낸다. 앱을 열 때마다 로그인 화면을 지나가는 셈이라, 이미 로그인돼 있으면
바로 일하는 화면이 뜨는 `/launch` 가 맞다. 세션이 없으면 어차피 미들웨어가
로그인으로 보낸다.

**`theme_color` 는 `#4f46e5`** — 로그인 화면과 주요 단추가 쓰는 indigo-600 이다.

## 4. 아이콘

`sharp` 가 이미 의존성에 있다(Next 의 이미지 최적화용, 8.17.3). 스크립트로
만든다 — 손으로 그린 PNG 를 저장소에 넣지 않는다.

`scripts/make-icons.mjs` 가 SVG 한 장에서 넷을 뽑는다:

| 파일 | 크기 | 쓰임 |
|---|---|---|
| `public/icons/icon-192.png` | 192 | 설치 조건 |
| `public/icons/icon-512.png` | 512 | 설치 조건 · 스플래시 |
| `public/icons/icon-512-maskable.png` | 512 | 안드로이드가 모양대로 깎는 것 |
| `public/icons/apple-touch-icon.png` | 180 | iOS 홈 화면 |

**maskable 은 여백이 다르다.** 안드로이드는 아이콘을 원·사각·물방울로 깎으므로
가장자리 20%가 잘려도 되게 그림을 가운데 60% 안에 넣는다. 같은 그림을 두
파일로 내는 이유가 이것이다.

**iOS 용은 투명 배경을 쓰지 않는다.** iOS 는 알파를 검게 칠한다.

그림은 indigo-600 바탕에 흰 「모아」다. 로고가 따로 생기면 그때 갈아 끼운다.

## 5. 서비스워커 — 아무것도 안 하는 것

`public/sw.js`. **루트 범위를 가지려면 루트에서 서빙돼야 한다** — 그래서
`public/` 이다.

```js
// 아무것도 안 한다. 설치 조건을 채우려고 있다.
//
// 캐싱을 넣지 않는다. 이 앱은 볼 것이 전부 서버에 있고 오프라인으로 할 일이
// 없다. 넣으면 "배포했는데 옛날 화면이 나온다"는 병이 새로 생기고, 그 병은
// 사용자가 스스로 못 고친다.
self.addEventListener('install', () => self.skipWaiting());
self.addEventListener('activate', (event) => event.waitUntil(self.clients.claim()));

// 이 핸들러가 있어야 크롬이 설치 가능으로 친다. respondWith 를 안 부르므로
// 요청은 평소대로 네트워크로 간다.
self.addEventListener('fetch', () => {});
```

**나중에 걷어내는 길을 지금 적어 둔다.** 서비스워커는 한번 깔리면 사용자
브라우저에 남는다. 없애려면 같은 주소에 `registration.unregister()` 만 하는
파일을 올려 한 번 돌게 해야 한다. 지금 것은 아무 응답도 가로채지 않아서
잘못돼도 화면을 망가뜨리지 못하지만, **길이 있다는 것은 알고 시작한다.**

### 등록하는 자리

`components/RegisterServiceWorker.jsx` — `'use client'`, 화면에 아무것도 안
그리고 `useEffect` 에서 한 번 등록한다. `app/layout.js` 의 `<body>` 안에 둔다.

`navigator.serviceWorker` 가 없으면 조용히 넘어간다. 실패해도 조용히 넘어간다 —
**설치는 편의이고, 실패를 배너로 띄우면 "앱이 고장났나"로 읽힌다.** 이 저장소가
멘션 자동완성과 24시간 경고에서 이미 쓰는 판단이다.

## 6. iOS 의 사정 — 미리 알고 시작한다

| | |
|---|---|
| 설치 프롬프트 | **없다.** 사용자가 공유 → 홈 화면에 추가를 직접 해야 한다 |
| 저장소 | 홈 화면 앱은 **사파리와 별개의 칸**을 쓴다 |
| 그래서 | **깔고 나면 그 안에서 다시 로그인해야 한다** |
| 아이콘 | `apple-touch-icon` 이 없으면 화면을 찍어서 쓴다 |

**다시 로그인하는 것이 고장으로 읽히기 쉽다.** 사파리에서는 들어가 있는데
홈 화면 앱에서는 로그인 화면이 뜬다. 그건 정상이고, 한 번 하면 그 안에서
유지된다. 이번에는 쓰는 사람이 하나라 문서로 충분하다.

`app/layout.js` 의 metadata 에 더한다. **기존 `title`·`description` 은 안
건드린다:**

```js
export const metadata = {
  title: '모아 MOA',
  description: '요구사항과 프로젝트를 한곳에 모읍니다.',
  manifest: '/manifest.json',
  appleWebApp: { capable: true, title: '모아', statusBarStyle: 'default' },
  icons: { apple: '/icons/apple-touch-icon.png' },
};

export const viewport = { themeColor: '#4f46e5' };
```

**`viewport` 를 따로 내보낸다.** Next 15 부터 `themeColor` 를 `metadata` 에
두면 빌드 경고가 난다.

## 7. 확인해야 알 수 있는 것 — 세션이 얼마나 사나

폰에 깔아 두고 주 1회 여는 앱이면, **그 사이 로그인이 풀려 있으면 껍데기는
의미가 없다.** Supabase 리프레시 토큰이 이 프로젝트에서 얼마나 유지되는지는
설정에 달렸고 지금 모른다.

**이번에 고치지 않는다.** 깔아 두고 며칠 뒤 열어 보면 답이 나온다. 풀려
있으면 그때가 세션 수명을 손볼 자리다.

## 8. 앞 단계에서 물린 것 — 이번에 해당하는 것

**① 렌더 테스트가 없다.** `environment: 'node'` 라 화면 회귀는 자동으로 안
잡힌다. 이번 것은 더하다 — **설치 가능 여부는 브라우저만 안다.**

**② 확인 전에 낡은 dev 서버를 죽인다.** 3단계에서 낡은 서버가 500을 냈고
하마터면 리팩터를 의심할 뻔했다. 서비스워커는 그보다 더하다 — **낡은 워커가
남아 있으면 고친 것이 반영이 안 된다.** 확인할 때는 개발자도구에서
「Update on reload」를 켜거나 워커를 지우고 본다.

**③ 로컬 dev 서버도 프로덕션 DB 를 본다.** 폰에서 로컬을 볼 일이 있으면
그 점을 잊지 않는다.

## 9. 테스트

**순수 함수로 뺄 것이 거의 없다.** 하지만 §2 의 그 한 줄은 **반드시 테스트로
못 박는다** — 조용히 깨지고, 본인 브라우저에서는 멀쩡해 보이는 종류다.

`middleware.matcher.test.js`:

- `middleware.js` 를 **글로 읽어** matcher 문자열을 뽑는다
  (`launchRouteGuard.test.js` 가 라우트 파일을 걸어 다니는 것과 같은 수법이다.
  `next/server` 를 import 하지 않아도 되고, 리터럴이 바뀌면 바로 잡힌다)
- 그 문자열로 `RegExp` 를 만들어 확인한다:

| 경로 | 기대 |
|---|---|
| `/manifest.json` | 안 걸린다 |
| `/sw.js` | 안 걸린다 |
| `/icons/icon-192.png` | 안 걸린다 |
| `/launch/abc` | **걸린다** |
| `/login` | **걸린다** (미들웨어가 통과시키는 것과 다른 문제다) |

`manifest.json` 의 내용도 확인한다 — `start_url`·`display`·192/512 아이콘이
있는지. 이 셋이 설치 조건이고, 하나라도 빠지면 설치 단추가 말없이 안 뜬다.

**기준선 78 파일 / 1233 테스트.** 줄면 안 된다.

## 10. 브라우저에서 볼 것 — 이 단계는 이게 검증의 전부다

| | |
|---|---|
| PC 크롬, 로그인 **전** | 매니페스트와 `sw.js` 가 200 으로 온다 (307 아님) |
| PC 크롬, 로그인 후 | 주소창에 설치 아이콘이 뜬다 |
| 설치 | 창이 떠서 열리고 `/launch` 가 나온다 |
| 안드로이드 크롬 | 「앱 설치」가 뜬다 |
| **아이폰 사파리** | 공유 → 홈 화면에 추가 → **아이콘이 화면 캡처가 아니다** |
| 아이폰, 깐 앱 열기 | 로그인 화면이 뜬다 (정상) · 로그인하면 그 안에서 유지된다 |
| 깐 앱에서 한 바퀴 | 런칭 보드 · 주간 진척 · 항목 창 · 요구사항 목록 |
| 배포 후 | 고친 화면이 **바로 반영된다** (캐싱을 안 넣은 것이 이 확인이다) |

**마지막 한 바퀴가 이번 작업의 진짜 목적이다.** 무엇이 폰에서 안 되는지
적어 온다. 그것이 다음 단계의 목록이 된다.

## 11. 안 하는 것

| | 왜 |
|---|---|
| 오프라인 캐싱 | 볼 것이 전부 서버에 있다. 낡은 화면 문제만 생긴다 |
| 푸시 | 폰에서 쓸 만한지부터 안다. 권한은 한 번 거절당하면 끝이다 |
| QR 팝업 | 찍기·로그인·설치 세 단계다. 지금은 본인 폰 하나면 된다 |
| 설치 유도 배너 | 쓰는 사람이 하나다 |
| 모바일 화면 고치기 | 무엇을 고칠지 §10 이 알려 준 뒤에 한다 |
| 스플래시 이미지 | 안드로이드는 아이콘과 색으로 만들어 준다. iOS 것은 기기마다 한 장씩이라 값이 안 맞는다 |
