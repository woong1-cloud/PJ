# 등급 어휘 정리와 전체관리자 해제 확인

2026-09-11. 설정 2단계-가를 배포한 뒤.

---

## 0. 무엇이 문제인가 — 재 봤다

직원 목록에서 「전체관리자」 뱃지와 「스파오 실무 관리자」가 한 줄에 같이 있고,
팀 배치 화면에서 어떤 사람의 등급이 이름 대신 **코드값 「2차」**로 보인다.
둘 다 증상이고, 원인은 하나다.

**「1차」가 두 가지 뜻으로 쓰이는데 그중 하나는 설정할 수가 없다.**

`TIER_LABELS['1차'] = '전체 관리자'` 다. 그런데 **브랜드별 등급으로는 1차를
저장할 수 없다** — `app/api/brand-team/route.js:51` 이 `['2차','3차','4차']`
만 받는다. 전체관리자는 등급이 아니라 별도의 깃발이고, 서버가 이렇게 판정한다:

```js
// lib/checkBrandAccess.js — 첫 줄이 전부다
if (isGlobalAdmin) return { allowed: true, tier: '1차' };
```

브랜드 배치도 소속도 기본등급도 그 아래 줄이라 **아예 안 읽힌다.**

### 어휘가 다섯 곳에서 다르다

| 어디 | 1차 | 2차 | 3차 | 4차 |
|---|---|---|---|---|
| 서버 (배치 저장) | ✕ | O | O | O |
| 팀 배치 화면 (`BrandTeamSection.jsx:14`) | ✕ | **✕** | O | O |
| 배치 창 (`BrandTeamAssignDialog.jsx:23`) | ✕ | **✕** | O | O |
| 직원 패널 (`MemberPanel.jsx:18`) | ✕ | O | O | O |
| 조직 기본등급 (`api/organizations`) | **O** | O | O | O |

조직 기본등급만 `TIER_RANK` 로 검사해서 **1차를 받는다.** 그리고 그 화면의
드롭다운도 `const TIERS = ['1차','2차','3차','4차']`
(`OrganizationSettings.jsx:16`)라 **사람이 1차를 고를 수 있다.** 서버가 안
막으니 저장된다 — 지금 「사업부문」에 그렇게 들어가 있다.

### 그 어긋남이 만드는 막다른 길

지금 「사업부문」의 기본등급이 **1차**로 저장돼 있다.

1. 사업부문 소속으로 가입한다
2. 관리자가 브랜드에 배치하려 하면 `suggestTierFromOrg` 가 **1차**를 제안하고
   `BrandTeamAssignDialog` 가 `setTier('1차')` 한다
3. 고를 목록에 1차가 없고, 보내면 서버가 **400 「유효하지 않은 tier입니다」**

**지금 사업부문 소속인 사람이 없어서 아직 안 터졌다.** 한 명 생기면 막힌다.

CAIO실(기본 2차)은 반쪽으로 같은 일을 겪는다. 서버는 2차를 받지만 두 화면의
목록에 2차가 없어서 **선택 상자가 이름 대신 「2차」를 그대로 보인다.** 그리고
그 상자를 열어 아무거나 고르면 **강등되고 그 화면에서는 되돌릴 수 없다.**

## 1. 고칠 규칙 — 한 곳에서 정한다

`lib/tiers.js`:

```js
// 브랜드별 등급은 셋뿐이다.
//
// 1차는 브랜드별 등급이 아니다. 전체관리자라는 별도의 깃발이고, 그 사람은
// 어느 브랜드에서든 1차로 **동작**할 뿐 1차로 **저장되지** 않는다
// (lib/checkBrandAccess.js 첫 줄). 여기에 1차를 넣으면 저장할 수 없는 값을
// 고를 수 있게 되어, 조직 기본등급이 그랬던 것처럼 막다른 길이 생긴다.
export const BRAND_TIERS = ['2차', '3차', '4차'];
```

**다섯 자리가 전부 이 목록을 본다.**

| 어디 | 지금 | 뒤 |
|---|---|---|
| `app/api/brand-team/route.js:51` | 배열 리터럴 | `BRAND_TIERS.includes(tier)` |
| `app/api/brand-team/[targetMemberId]/route.js:16` | 배열 리터럴 | 같음 |
| `app/api/organizations/route.js:41` | `TIER_RANK` | `BRAND_TIERS` |
| `app/api/organizations/[id]/route.js:30` | `TIER_RANK` | 같음 |
| `components/BrandTeamSection.jsx:14` | `['3차','4차']` | `BRAND_TIERS` |
| `components/BrandTeamAssignDialog.jsx:23` | `['3차','4차']` | `BRAND_TIERS` |
| `components/settings/MemberPanel.jsx:18` | `['2차','3차','4차']` | `BRAND_TIERS` |
| `components/OrganizationSettings.jsx:16` | `['1차','2차','3차','4차']` | `BRAND_TIERS` |

**두 화면이 2차를 얻는다.** 그게 팀 배치의 「2차」 코드값과 되돌릴 수 없는
강등을 동시에 없앤다.

**브랜드 관리자가 남을 자기와 같은 등급으로 올릴 수 있게 된다.** 그래도
된다고 본다 — 서버가 이미 허용하고 있었고, 직원 패널도 이미 준다. 두 화면만
빠져 있던 것이 규칙이 아니라 누락으로 읽힌다.

## 2. 데이터 한 줄

규칙만 고치면 **「사업부문」에 저장된 1차는 그대로 남는다.** 목록에 없는 값이라
화면에 코드값으로 뜨고, 제안도 여전히 1차다.

```sql
update organizations set default_tier = '2차' where name = '사업부문';
```

**사용자가 직접 돌린다.** 그리고 이런 값이 또 생기지 않도록 §1 의 규칙이
막는다.

**마이그레이션 파일로 만들지 않는다.** 한 조직의 값 하나이고, 이름이 바뀌면
안 맞는 SQL 이 저장소에 남는다. 조직 화면에서 손으로 고쳐도 된다 — 규칙이
고쳐진 뒤라면 그 화면이 2차를 준다.

## 3. 화면 넷

### ① 전체관리자 줄이 실제 권한을 말한다

지금 「전체관리자」 뱃지와 「스파오 실무 관리자」가 한 줄에 있다. 두 칸이
「이 사람이 뭘 할 수 있나」에 다른 답을 한다. 저장된 등급은 **지금 그 사람이
할 수 있는 일이 아니다.**

```
변기석 [전체관리자]   본부 소속 미지정   모든 브랜드 · 전체 관리자
                                      해제하면: 스파오 실무 관리자 — 이 하나뿐입니다
```

**저장값을 숨기지 않는다.** 처음 목업에서 숨겼는데 틀렸다. **전체관리자를
해제하는 순간 그 값이 살아난다** — 안 보이면 무엇이 남는지 모르는 채로 권한을
끊게 된다.

### ② 소속이 없는 사람을 보이게 한다

「본부」를 흐리게 하고 「소속 미지정」을 붙인다. 그들만 찾는 필터도 둔다.

**지금 세 명이고 전부 전체관리자다**(장재혁 · 변기석 · 한지웅). 옛 자유 입력
`affiliation='본부'` 만 있고 `organizations` 로 이관이 안 됐다. 그 사람들은
소속도 기본등급도 없어서, 전체관리자를 해제하면 기댈 것이 저장된 배치뿐이다.

### ③ 팀 배치의 코드값이 사라진다

§1 이 목록에 2차를 넣으면 저절로 풀린다. 화면에서 따로 할 일이 없다.

### ④ 조직의 빈 기본등급이 무엇이 되는지 말한다

지금 법무·재무가 비어 있고 화면에는 「—」다. 「안 정함」인지 「요청자로 정함」
인지 구별이 안 된다. 실제로는 `suggestTierFromOrg` 가 **4차로 떨어뜨린다.**

```
재무    요청자 (안 정함 — 기본값)
```

## 4. 전체관리자 해제 확인

**지금은 점 세 개에서 「전체관리자 해제」를 누르면 바로 해제된다.**
(`TeamMemberListSection.jsx:69` → `patchMember(m, { isGlobalAdmin: false })`)

### 왜 확인을 받나

해제하면 **저장된 브랜드 배치로 떨어진다.** 지금 값으로 계산하면:

| 사람 | 저장된 배치 | 해제 뒤 실제로 들어갈 수 있는 곳 |
|---|---|---|
| 한지웅 | 미쏘 · 로엠 · 후아유 · 스파오 (4) | **미쏘 · 스파오** — 둘은 브랜드가 비활성 |
| 변기석 | 스파오 (1) | **스파오 하나뿐** |
| 장재혁 | 스파오 (1) | **스파오 하나뿐** |
| 김유나 | 신규 브랜드 (1) | 신규 브랜드 하나 |

**저장된 개수만 보면 안전해 보이는데 실제는 절반일 수 있다.** 한지웅이
그렇다. 비활성 브랜드는 배치가 있어도 못 들어간다 —
`/api/my-brands` 가 걸러낸다.

### 무엇을 묻나

해제를 누르면 창이 뜬다. 담을 것:

```
한지웅 님의 전체관리자를 해제합니다

해제하면 저장된 브랜드 배치로 돌아갑니다.

  들어갈 수 있는 곳        미쏘 · 스파오   (둘 다 실무 관리자)
  들어갈 수 없게 되는 곳    신규 브랜드
  배치가 있지만 못 들어감   로엠 · 후아유   (브랜드가 비활성)

                                    [취소]  [해제]
```

**「들어갈 수 없게 되는 곳」이 핵심이다.** 지금 전체관리자라 모든 활성 브랜드를
보고 있는데, 해제하면 배치가 없는 브랜드는 사라진다.

**남는 곳이 하나도 없으면 더 세게 말한다.** 「이 사람은 어느 브랜드에도 못
들어가게 됩니다」. 막지는 않는다 — 비활성화하려는 것일 수도 있다.

### 안 묻는 것

**「전체관리자 지정」은 확인을 안 받는다.** 권한을 주는 일이고, 되돌리는 길이
바로 옆에 있다.

**마지막 전체관리자는 서버가 이미 막는다**(`lib/checkLastGlobalAdmin.js`).
창에서 다시 세지 않는다 — 두 곳이 세면 언젠가 갈라진다. 창은 서버가 돌려준
400 을 그대로 보인다.

### 순수 함수로 뺀다

`lib/globalAdminDemote.js`:

```js
// 전체관리자를 해제하면 어디에 남고 어디를 잃나.
//
// 창에서 세지 않고 여기서 센다 — 화면은 이 결과를 그리기만 한다.
// 비활성 브랜드를 따로 가르는 이유: 배치가 있어도 /api/my-brands 가
// 걸러내서 실제로는 못 들어간다. 개수만 세면 안전해 보이는데 실제는
// 절반일 수 있다(한지웅이 그렇다).
export function demoteImpact({ brandRoles, brands }) {
  // → { keep: [{ name, tier }], lose: [name], inactive: [name] }
}
```

- `keep` — 배치가 있고 브랜드가 활성. 해제 뒤에도 들어간다
- `lose` — 활성 브랜드인데 배치가 없다. 지금은 보이지만 해제하면 사라진다
- `inactive` — 배치는 있는데 브랜드가 비활성. 어차피 못 들어간다

## 5. 안 바꾸는 것

| | 왜 |
|---|---|
| 사다리 구조 | 요청자·실무자·실무 관리자·전체관리자. 멀쩡하다 |
| 저장값 `1차`~`4차` | 이름표는 이미 사람 말이다. 저장값을 갈면 마이그레이션과 기존 데이터가 다 걸린다 |
| `TIER_RANK` 에서 1차 빼기 | `checkBrandAccess` 가 전체관리자에게 `tier: '1차'` 를 돌려주고 그 값이 순위 비교에 쓰인다. 빼면 그게 깨진다 |
| 제안 등급을 목록에 보이기 | 한 줄에 등급이 둘로 보인다. 제안은 배치하는 순간에만 뜻이 있다 |
| 비활성 브랜드 접근 막기 | `checkBrandAccess` 는 활성 여부를 안 본다. 지금 그런 사람이 없고, 손대면 범위가 는다. **따로 본다** |
| 비활성화(재직) 확인 | 같은 종류지만 이번 범위가 아니다. 여러 줄 일괄과 함께 본다 |
