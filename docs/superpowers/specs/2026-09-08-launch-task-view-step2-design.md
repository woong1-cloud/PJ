# 런칭 2단계 — 항목 링크와 보기 창

2026-09-08. 1단계 배포 뒤 정리한 스펙.

바탕: `2026-09-08-launch-url-and-task-view-design.md` §2 — 그 절을 구현 가능한
수준으로 푼다. 목업: `agent/pj/launch-task-view.html`

---

## 0. 1단계가 남겨 둔 자리

`parseLaunchParams` 는 **이미 `task` 를 파싱한다**(`lib/launchFilters.js:48`).
**아무도 안 쓴다.** 2단계가 그것을 소비한다.

```js
task: get('task'),   // 항목 코드. 2단계에서 보기 창을 연다.
```

`PATCH /api/launch/[id]/tasks/[taskId]` 는 **이미 `assignee` 를 받는다**
(그 파일 78줄, 가드는 `requireLaunchAccess(id, 'member')`). 「나에게 맡기」에
**서버 변경이 없다.**

## 1. 1단계에서 배운 것 — 규칙으로 남긴다

세 가지가 실제로 물렸다. 2단계 구현이 같은 자리를 다시 밟는다.

**① 숫자는 그것이 데려가는 곳과 같아야 한다.**
「N건 중 M건」이 실제로 그려지는 목록이 아닌 것을 세고 있었고, 주간 진척의
「기한 지남 2」를 누르면 0건이 떴다. 2단계에서 이 함정이 있는 자리 —
「풀림 4」를 눌러 연 창의 후행 목록이 정말 4건인가, 「나에게 맡기」 뒤
「내 담당」 숫자가 곧바로 1 오르는가.

**② `task.assignee` 는 객체다, 문자열이 아니다.**
목록 API 가 `assignee:team_members!launch_tasks_assignee_fkey(id, name)` 로
붙여 준다. `lib/launchMembers.js` 의 **`assigneeId(task)`** 를 쓴다.
1단계에서 이걸 몰라 「내 담당」이 늘 0이었다 — **담당자가 없어서 0인 것과
비교가 깨져 0인 것이 화면에서 똑같이 보인다.**

**③ effect 의 ref 는 가드가 통과한 뒤에 태운다.**
`launch` 가 아직 안 온 첫 렌더에 태우면 데이터가 늦게 올 때 영영 안 돈다.

## 2. `?task=` 를 누가 소비하나

**주소가 하나뿐인 출처다.** 지금 창을 여는 길이 셋인데 전부 `onParams` 로 모은다.

| 입구 | 지금 | 2단계 |
|---|---|---|
| 「풀림 N」 배지 | `setLinksFor(task)` | `onParams({ task: task.code })` |
| 선행 칩(`DepChip`) | `setLinksFor(task)` | 같음 |
| **줄 제목 클릭** | **없음** | 같음 |
| 링크로 도착 | 없음 | 페이지가 `task` 를 내려 준다 |

`LaunchBoard` 의 `linksFor` **state 를 없앤다.** 창은 `task` prop 이 있으면 열린다.
닫기는 `onParams({ task: '' })`.

**창 안에서 연계를 타고 옮겨 다닐 때도 주소를 고친다.** `18-22 → 18-12` 로 가면
`?task=18-12` 가 된다 — 지금 보고 있는 것을 주소가 가리켜야 링크를 보낼 수 있다.
`TaskLinksDialog` 안의 로컬 `code` state 를 없애고 prop 으로 받는다.

**전부 `replace` 다.** 9단짜리 줄을 타면 히스토리가 아홉 칸 쌓인다.

## 3. 못 찾은 코드

`?task=99-99` — 지워졌거나 다른 런칭의 항목이다.

- **창을 반드시 닫는다.** 안 닫으면 안내는 "99-99 를 못 찾았습니다"인데 창에는
  지난 항목이 떠 있다. **목업에서 실제로 이 버그가 났다.**
- 툴바 아래 한 줄로 말한다. 조용히 넘기지 않는다 — 링크를 누른 사람은 무언가
  열릴 것을 기대했다.
- `?task=` 는 주소에 그대로 둔다. 지우면 왜 안 열렸는지 묻는 사람에게 줄
  근거가 사라진다.

## 4. 필터 밖 항목을 가리킬 때

`?view=ready&task=18-22` 인데 18-22 는 막힘이다.

**창은 열되 보기를 안 바꾼다.** 링크가 뜻한 필터를 마음대로 바꾸지 않고,
창을 닫으면 원래 보려던 목록이 그대로 있다.

## 5. 창 — `TaskLinksDialog` → `TaskViewDialog`

지금 항목 창이 넷이다(고치기·연계·막힘·해당없음). **다섯째를 만들지 않는다.**
`TaskLinksDialog`(261줄)가 이미 「한 항목을 보는 창」이다 — 선행·후행을 오가고
`onEdit` 로 고치기에 넘긴다. 여기에 기본 정보를 얹고 이름을 바꾼다.

```
18-22  물류 창고 계약                      [막힘]  [고치기] ✕   ← 머리 고정
호카 HOKA · D30_물류구축
──────────────────────────────────────────────────────────
기한   2026-09-30 D-62      담당자  없음 「나에게 맡기」        ← 몸통 스크롤
주관   물류팀               지원    재무팀
결정권 CAIO실               고친이  변기석 · 9/5
⚠ 결정 대기 · 물류 3PL 최종 선정
선행 ↑ 18-12 인프라 설계 [완료] D-91
후행 ↓ 18-25 · 18-26 · 2건 더 보기          풀림 4건
```

**머리·발 고정, 몸통만 스크롤.** 3단계에서 활동이 붙으면 창 높이가 늘어난다 —
그때 입력칸이 댓글 12건 아래로 밀리지 않게 지금 구조를 잡아 둔다.

**실측**(목업, 가로 넘침 0): 1280×800 → 창 672×750, 몸통 556 · 발 122.
1280×620 → 570, 몸통 376. 400×720 → 366×670. 창은 늘 화면보다 50px 작다.

**제목 클릭을 고치기(폼)에 연결하지 않는다.** 참여자가 처음 보는 화면이 폼이면
"내가 뭘 고쳐야 하나"로 읽힌다. 보는 게 먼저고 고치기는 한 번 더다.

**「고치기」를 누르면 보기 창을 닫고 `TaskEditDialog` 를 연다**(지금 `onEdit` 가
하는 일 그대로). `?task=` 는 **그대로 둔다** — 같은 항목을 보고 있다. 고치기를
닫으면 보기 창으로 돌아온다.

## 6. 「나에게 맡기」

담당자가 비어 있을 때만 이름 자리에 밑줄 링크 한 줄.

```
담당자   없음  나에게 맡기
담당자   한지웅  놓기        ← 누른 뒤
```

`PATCH .../tasks/<id>` 에 `{ assignee: myMemberId }`. **서버 변경 없다.**
「놓기」는 `{ assignee: null }`.

**드롭다운으로는 0/471 을 못 채운다.** 드롭다운은 "내가 후보에 있나"부터 알아야
하고(`assigneeCandidates` 는 그 항목의 주관 역할 참여자만 준다), 없으면 왜 없는지도
모른다. 한 번 누르면 끝나는 길이 따로 있어야 한다.

**주관 역할 참여자가 아니어도 누를 수 있다.** 역할 배정이 느슨하고, "내가 하겠다"를
막을 이유가 없다. 서버는 `requireLaunchAccess` 만 본다.

**기존 담당자가 있으면 이 링크를 안 그린다.** 남의 일을 한 번 눌러 가져가는 자리가
되면 안 된다 — 그때는 고치기 창의 드롭다운으로 바꾼다.

**응답으로 온 줄을 그대로 갈아 끼운다**(`onChanged`). 통째로 다시 부르면 스크롤이
튀고, 회의 중에 그러면 보던 자리를 잃는다. 그리고 **「내 담당」 숫자가 그 자리에서
1 올라야 한다** — 안 오르면 §1①의 그 실패다.

## 7. 안 하는 것

| | 왜 |
|---|---|
| `/launch/[id]/tasks/[code]` 라우트 | `?task=` 로 충분. 라우트를 만들면 필터·스크롤 복원이 숙제가 된다 |
| 댓글·멘션 | 3단계 |
| 「기록」 탭 | 런칭에 이력 자료가 없다. 빈 탭을 안 만든다 |
| 하위 작업·연결된 업무 항목 | 선행조건이 이미 낫다 |
| 담당자 이름 드롭다운을 주소로 | 「나에게 맡기」가 uuid 를 채우기 시작한 뒤에 합친다 |

## 8. 테스트

`environment: 'node'` 라 렌더 테스트가 없다. 순수 함수로 잡는다.

**`lib/launchMembers.test.js`** — `assigneeId` 는 이미 넷 있다(1단계 끝에 추가).

**`lib/launchFilters.test.js`** (더하기)
- `?task=` 는 코드 그대로 온다 (이미 있음)
- `mergeLaunchParams(base, { task: '' })` 가 키를 지운다

**새로 만들 것 — `lib/launchTaskLink.js`**
창을 여는 판정을 화면에서 빼서 테스트한다.
```js
// 주소의 코드로 항목을 찾는다. 못 찾으면 왜 못 찾았는지까지 준다 —
// 화면이 "그 항목을 못 찾았습니다"를 띄울 근거다.
export function taskByCode({ tasks, code }) // → { task, missing }
```
- 있는 코드 → `{ task, missing: '' }`
- 없는 코드 → `{ task: null, missing: '99-99' }`
- 빈 코드 → `{ task: null, missing: '' }` (창을 안 연다, 안내도 안 띄운다)

## 9. 위험한 자리

**① 창이 안 닫히는 것.** 못 찾은 코드에서 이전 항목이 남는다(목업에서 났다).
`TaskEditDialog` 주석의 그 병과 같다 — "닫혀도 계속 그리면 지난 항목의 값이
그대로 남는다".

**② 「풀림 N」 숫자와 창 안의 후행 개수가 갈리는 것.** 둘 다
`lib/launchDeps.js` 의 `linksOf` 에서 와야 한다. 창이 따로 세면 갈린다.

**③ 담당자를 바꾼 뒤 숫자가 안 따라오는 것.** §6 마지막 문단.
