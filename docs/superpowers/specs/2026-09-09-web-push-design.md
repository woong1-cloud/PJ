# PWA 3단계 — 웹 푸시

2026-09-09. 설치 안내 다음.

---

## 0. 무엇을 얻나 — 그리고 못 얻나

**얻는 것은 속도지 도달이 아니다.** 지금도 메일이 간다. 푸시가 더하는 것은
"메일함을 열지 않아도 지금 안다"이다.

**못 얻는 것을 먼저 적는다.** 아이폰에서 푸시는 **홈 화면에 깐 사람만**
받는다. 그러니 푸시의 도달 범위는 **설치한 사람 수를 절대 못 넘는다.**
2단계(설치 안내)가 먼저인 이유가 이것이다.

## 1. 무엇을 푸시로 보내나 — 둘뿐

지금 메일이 나가는 사건은 셋이다.

| 사건 | 벨 | 메일 | **푸시** | 왜 |
|---|---|---|---|---|
| 협조 요청 | O | O | **O** | "당신이 답해야 그 건이 움직인다." 기다리는 사람이 있다 |
| 멘션 | O | O | **O** | 이름을 불렀다. 대화가 멈춰 있다 |
| 주간 요약 | - | O | **X** | 훑는 것이다. 지금 답할 것이 아니다 |

**셋 다 보내면 소음이 되고, 소음이 되면 끈다.** 한 번 끄면 급한 것도 같이
꺼진다. 그래서 **지금 답이 필요한 것만** 푸시로 보낸다.

댓글 하나하나는 푸시로 안 보낸다. 멘션이 아닌 댓글은 그 항목을 보는 사람이
읽으면 되는 것이다.

## 2. 메일을 끄나 — 안 끈다

**푸시를 켠 사람의 협조요청·멘션 메일을 끌까**를 고민했다. 안 끈다.

**푸시는 갔는지 알 수 없다.** 구독이 죽었을 수도, 권한이 취소됐을 수도,
폰이 꺼져 있을 수도 있다. 우리가 받는 것은 "밀어 넣었다"까지고 "봤다"가
아니다. 메일은 그 영수증이다.

그리고 이 둘은 **드문 사건이다.** 협조 요청은 회의 뒤에 몇 건, 멘션은
가끔이다. 드문 일이 두 번 오는 것은 견딜 만하고, 급한 것을 놓치는 것은
안 그렇다.

**나중에 시끄러우면 그때 설정을 하나 늘린다.** 지금 미리 만들지 않는다 —
켠 사람이 아직 없어서 시끄러운지 알 방법이 없다.

## 3. 권한은 언제 묻나 — 누른 사람에게만

**이것이 이 단계에서 제일 중요한 결정이다.**

알림 권한은 **한 번 거절당하면 다시 못 묻는다.** 브라우저가 그 주소를
기억하고, 사용자가 설정에 들어가 직접 풀어야 한다. 자동으로 뜨는 권한
요청은 대부분 거절당한다 — 왜 묻는지 모르는 상태에서 뜨기 때문이다.

**그래서 우리가 먼저 묻지 않는다.** 설정 화면의 「알림 받기」를 **사람이
누를 때만** `Notification.requestPermission()` 을 부른다. 그 사람은 방금
자기 손으로 "알림을 받겠다"고 말한 참이다.

로그인 직후에도, 협조 요청을 받은 뒤에도, 소식 팝업에서도 안 묻는다.

## 4. 못 쓰는 상태가 셋이다 — 화면이 구분해야 한다

**여기를 뭉뚱그리면 기능이 고장난 것으로 읽힌다.** 토글이 안 먹는 것과
아직 켤 수 없는 것은 완전히 다른 말이다.

| 상태 | 어떻게 아나 | 화면이 뭐라고 하나 |
|---|---|---|
| **아이폰인데 안 깔았다** | `display-mode: standalone` 이 아니고 iOS | 「홈 화면에 추가한 뒤에 켤 수 있습니다」 + `/install` 링크 |
| **이미 거절했다** | `Notification.permission === 'denied'` | 「브라우저 설정에서 알림을 허용해야 합니다」. **토글을 안 그린다** — 눌러도 아무 일이 안 일어난다 |
| **브라우저가 지원 안 함** | `PushManager` 가 없다 | 「이 브라우저는 알림을 지원하지 않습니다」 |
| 켤 수 있다 | 위 셋이 아니다 | 토글 |

**아이폰 것을 특히 조심한다.** 사파리로 열어 놓고 토글을 누르면 iOS 는
조용히 실패한다. 그 화면을 본 사람은 "모아 알림은 안 되는구나"로 결론
내리고 다시 안 온다.

## 5. 데이터 — `push_subscriptions`

마이그레이션 `0038`. **사용자가 직접 돌린다.**

```sql
create table if not exists push_subscriptions (
  id uuid primary key default gen_random_uuid(),
  team_member_id uuid not null references team_members(id) on delete cascade,
  endpoint text not null unique,
  p256dh text not null,
  auth text not null,
  user_agent text,
  created_at timestamptz not null default now(),
  last_ok_at timestamptz
);
create index if not exists idx_push_subscriptions_member on push_subscriptions (team_member_id);
```

**한 사람이 여러 줄을 갖는다.** 폰과 PC 와 태블릿이 각각 다른 구독이다.
`endpoint` 가 열쇠이고 그것이 `unique` 다 — 같은 기기가 다시 구독하면
새 줄이 아니라 같은 줄이다.

**`on delete cascade` 를 건다.** 팀원이 지워지면 그 사람의 구독도 함께
없어져야 한다. 남으면 없는 사람에게 계속 밀어 넣는다.

## 6. 열쇠(VAPID) — 내가 만지지 않는다

푸시는 VAPID 키 한 쌍이 필요하다. **사용자가 직접 만들고 직접 넣는다.**

```
npx web-push generate-vapid-keys
```

| 환경변수 | |
|---|---|
| `VAPID_PUBLIC_KEY` | 서버가 읽어 `/api/push/key` 로 내려 준다 |
| `VAPID_PRIVATE_KEY` | **서버만.** 어디에도 찍지 않는다 |

**`NEXT_PUBLIC_` 을 안 쓴다.** 그러면 빌드 시점에 값이 있어야 하는데,
배포 플랫폼이 빌드 전에 넣는 값이 지금 넷이고 거기에 묶이는 것을 늘리지
않는다. 라우트로 내려 주면 런타임 값이면 된다.

**개인 키를 대화·문서·ZIP 어디에도 남기지 않는다.** 이 저장소는 예전에
서비스 키가 화면 캡처로 새어 나간 적이 있다. 같은 일을 반복하지 않는다.

## 7. 서비스워커가 처음으로 일을 한다

지금 `public/sw.js` 는 **아무것도 안 한다.** 설치 조건을 채우려고 있을
뿐이고, 그래서 잘못돼도 화면을 못 망가뜨린다.

**이번에 그게 바뀐다.** `push` 와 `notificationclick` 이 생긴다.

```js
self.addEventListener('push', (event) => { /* 알림을 그린다 */ });
self.addEventListener('notificationclick', (event) => { /* 그 화면을 연다 */ });
```

**`fetch` 는 여전히 아무것도 안 한다.** 캐싱은 이번에도 안 넣는다. 이유는
1단계와 같다 — 오프라인으로 할 일이 없고, 넣으면 "배포했는데 옛날 화면이
나온다"가 생긴다.

**워커가 바뀌면 이미 깐 사람들의 것도 갱신돼야 한다.** `skipWaiting` 과
`clients.claim()` 이 이미 있어서 새로고침 한 번이면 바뀐다. 확인할 때
개발자도구에서 낡은 워커를 지우고 본다 — **1단계에서 스펙에 적어 둔 그
함정이다.**

### 알림을 눌렀을 때

`notificationclick` 이 그 항목을 연다. 협조 요청이면 `?task=<코드>`,
멘션이면 그 요구사항이다. **이미 열린 창이 있으면 새 창을 만들지 않고 그
창을 가져다 쓴다** — 안 그러면 누를 때마다 창이 쌓인다.

## 8. 죽은 구독을 치운다

**이걸 안 하면 표가 시체로 찬다.** 앱을 지우거나 알림을 끄면 구독이
죽는데, 죽었다고 알려 주지 않는다. 보낼 때 알게 된다.

푸시 서비스가 **404 나 410** 을 주면 그 구독은 끝난 것이다. **그 줄을
지운다.** 다른 오류(429, 500)는 일시적이라 안 지운다.

**이 판정을 순수 함수로 뺀다** — `lib/pushCleanup.js` 의
`isGone(statusCode)`. 잘못 지우면 멀쩡한 사람이 알림을 잃고, 그건 조용히
일어난다.

## 9. 라우트

```
GET    /api/push/key          공개 키를 준다
POST   /api/push/subscribe    { endpoint, keys } 를 저장한다
DELETE /api/push/subscribe    { endpoint } 를 지운다 (토글을 끄면)
```

셋 다 **로그인한 사람**이어야 한다. 구독은 사람에 묶이므로 `getSessionMember`
가 준 id 를 쓴다 — **화면이 보낸 값을 안 믿는다.** 믿으면 남의 알림을 자기
폰으로 받아 갈 수 있다.

**`launchRouteGuard.test.js` 는 이 라우트들을 안 본다.** 그 테스트는
`app/api/launch/**` 만 걸어 다닌다. 문지기는 사람이 지켜야 한다.

## 10. 보내는 자리

`lib/notify.js` 다. `notifyHelpRequest` 와 멘션 알림이 벨과 메일을 보내는
그 자리에 셋째 줄이 붙는다.

**절대 throw 하지 않는다.** 이 저장소가 이미 정한 규칙이다 — 푸시가
실패했다고 「요청 실패」를 보이면 안 된다. 댓글은 이미 저장됐다.

**보내기를 기다리지 않는 것을 고민한다.** 지금 메일은 `await` 한다. 구독이
사람당 여럿이면 왕복이 는다. 다만 메일이 이미 그러고 있어서, **이번에
바꾸면 두 곳의 규칙이 갈라진다.** 같이 두고, 느려지면 그때 둘 다 바꾼다.

## 11. 테스트

렌더 테스트가 없다(`environment: 'node'`). 순수 함수로 뺄 수 있는 것을
빼서 그것만 못 박는다.

| 파일 | 무엇 |
|---|---|
| `lib/pushCleanup.js` | `isGone(404)`·`isGone(410)` 은 참, `429`·`500`·`201` 은 거짓 |
| `lib/pushPayload.js` | 협조요청·멘션의 제목·본문·링크. 항목 하나면 `?task=`, 여럿이면 런칭 |
| | 제목이 길면 자른다 (`truncateTitle` 을 다시 쓴다 — 벨·메일과 규칙이 갈라지면 안 된다) |

**기준선은 2단계가 끝난 시점의 수.** 줄면 안 된다.

**푸시가 실제로 오는지는 테스트가 못 잡는다.** 폰에서 봐야 한다.

## 12. 브라우저에서 볼 것

| | |
|---|---|
| 설정 — 안 깐 아이폰 | 「홈 화면에 추가한 뒤에」 + 링크. **토글이 없다** |
| 설정 — 깐 아이폰 | 토글이 있다 |
| 토글 켜기 | 권한 창이 **그때** 뜬다 |
| 협조 요청 받기 | **폰에 알림이 온다** |
| 알림 누르기 | 그 항목이 열린다. 창이 안 쌓인다 |
| 여러 기기 | 폰과 PC 둘 다 온다 |
| 토글 끄기 | 그 기기에만 안 온다. 다른 기기는 계속 온다 |
| 앱 지우고 보내기 | 오류가 안 나고, 그 구독이 표에서 **사라진다** |
| 주간 요약 | **푸시로 안 온다** (메일만) |

## 13. 안 하는 것

| | 왜 |
|---|---|
| 주간 요약 푸시 | §1 — 훑는 것이다 |
| 댓글마다 푸시 | §1 — 멘션이 아니면 보는 사람이 읽으면 된다 |
| 푸시 켠 사람 메일 끄기 | §2 — 갔는지 알 수 없다. 나중에 |
| 자동 권한 요청 | §3 — 한 번 거절당하면 끝이다 |
| 배지 숫자 | 아이폰은 깐 앱만 되고 지원이 고르지 않다. 값이 안 맞는다 |
| 알림에 답장 달기 | 답은 항목의 대화에 남아야 한다. 알림에서 쓰면 그 맥락 밖에 남는다 |
| 오프라인 캐싱 | §7 — 1단계와 같은 이유 |
