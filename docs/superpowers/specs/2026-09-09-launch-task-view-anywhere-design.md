# 런칭 4단계 — 어느 탭에서든 항목 열기

2026-09-09. 3단계 배포 뒤.

---

## 0. 무엇이 문제인가

주간 진척은 항목을 **줄로 보여주는데 열 수가 없다.** 회의에서 「막힘 5건」을
훑다가 하나를 보려면 「보드에서 열기」로 탭을 옮겨야 하고, 그러면 **보던 자리를
잃는다.** 그건 그 화면을 만든 이유와 어긋난다.

3단계에서 항목 창에 댓글까지 붙었는데, 정작 **회의 중에 그 창을 열 수 있는
자리가 보드 하나뿐이다.**

## 1. 왜 링크만으로는 안 되나

`?task=` 는 이미 있다. 주간 진척 줄에 그 링크를 달면 **탭이 보드로 튕긴다** —
창이 `LaunchBoard` 안에 있고 `LaunchBoard` 는 `tab === 'board'` 일 때만
그려지기 때문이다.

**창을 페이지로 올려야 한다.** 그러면 탭과 무관하게 열린다.

## 2. 어제 잘못 말한 것 — 옮기는 거리가 짧지 않다

처음에 "페이지가 이미 `taskCode` 를 갖고 있으니 옮기는 거리가 짧다"고 했는데
**틀렸다.** 창이 `LaunchBoard` 안의 것들에 물려 있다:

| 창이 쓰는 것 | 어디 | 다른 사용처 |
|---|---|---|
| `patchTask(task, body)` | `LaunchBoard:464` | **5곳** — 상태 단추 · 해당없음 · 되돌리기 · 나에게 맡기 · 막힘 |
| `busy` (지금 PATCH 중인 항목 id) | `LaunchBoard:109` | 7곳 |
| `taskDialog` + `TaskEditDialog` | `LaunchBoard:131, 1058` | 「고치기」 · 「＋ 항목」 |

창만 올리면 이 셋이 따라 올라간다.

## 2-A. 실제로 고른 것 — 창을 안 올렸다 (2026-09-09)

**아래 §3 이 옳은 모양이지만 이번에는 안 했다.** 대신 보드를 탭 밖에서도
마운트한 채 감췄다:

```jsx
{tab === 'board' && <LaunchBoard/>}   →   <div hidden={tab !== 'board'}><LaunchBoard/></div>
```

창이 `DialogPortal` 로 `document.body` 에 그려지므로 부모의 `display:none` 을
탈출한다(`components/ui/dialog.jsx:56`). 그래서 주간 진척 탭에서도 창이 뜬다.

**왜 이쪽인가.** 사용자에게는 두 방법이 **완전히 같게 보인다**(목업:
`agent/pj/step4-ga-vs-na.html`). 차이는 값과 위험뿐이다:

| | 감추기 | 올리기(§3) |
|---|---|---|
| 시간 | 20분 | 2시간 |
| 깨질 수 있는 자리 | 거의 없음 | **여덟** — 상태 단추 넷·해당없음·되돌리기·막힘·＋항목 |
| 남는 값 | 471줄이 늘 DOM 에 | 없음 |

**여덟 자리가 전부 렌더 테스트로 안 잡힌다**(`environment: 'node'`). 빌드도
1200개 테스트도 다 통과한 채로 상태 단추가 안 먹을 수 있다. 지금 그 위험을
지는 이유가 **"주간 진척에서 줄 하나 누르기"** 하나뿐이라 비율이 안 맞는다.

**언제 §3 으로 가나.** 결정 대기에서도 항목을 열고 싶어질 때. 그때는 이유가
둘이 되고, 감추기로는 안 된다(그 화면은 항목을 아예 안 그린다 — §7).

**남은 값 둘.**
- 471줄이 늘 DOM 에 있다. `display:none` 이라 레이아웃·페인트는 건너뛰지만
  리렌더는 돈다. 471건에서는 체감되지 않았다.
- 주간 진척으로 바로 들어와도 보드가 마운트되어 역할 승격 effect 가 돌고
  주소에 `&role=` 이 붙는다. 해롭지 않지만 없던 일이다.

## 3. 무엇이 맞는 모양인가

**이 셋은 원래 페이지 것이다.** `patchTask` 는 "이 런칭의 항목 하나를 고친다"
이지 "보드에서 고친다"가 아니다. 보드는 그 함수를 **쓰는** 화면 중 하나일 뿐이고,
지금은 창까지 둘이 됐다.

```
지금                        4단계
─────                       ─────
page                        page
 └ LaunchBoard               ├ patchTask · busy
    ├ patchTask · busy       ├ TaskViewDialog   ← 탭과 무관하게
    ├ TaskViewDialog         ├ TaskEditDialog
    ├ TaskEditDialog         ├ BlockDialog · NotApplicableDialog
    └ 보드 UI                └ LaunchBoard (onPatch, busy 를 props 로)
```

**막힘 창(`BlockDialog`)과 해당없음 창(`NotApplicableDialog`)도 같이 올린다.**
둘 다 `patchTask` 를 쓰고, 보기 창에서 상태를 바꾸는 길이 생기면 거기서도
필요하다. 남겨 두면 `patchTask` 가 두 곳으로 갈라진다.

## 4. 세 탭의 사정이 다르다

| 탭 | 지금 | 4단계 |
|---|---|---|
| **주간 진척** | 항목을 줄로 그림 (`TaskLine`) | **줄을 누르면 열린다** |
| **결정 대기** | 「막힌 항목 5건이 이것을 기다립니다」 — **숫자만** | 안 한다 (§7) |
| **간트** | 막대가 **워크스트림**이지 항목이 아님 | 안 한다 (§7) |

**주간 진척은 `TaskLine` 하나만 고치면 된다.** ②막힘 · ③기한 지남 · ④이번 주
마감 · ⑤이번 주 완료가 전부 그 컴포넌트를 쓴다(`WeeklyProgress.jsx:171`).
①결정 대기만 다른 줄이고, 그건 항목이 아니라 결정이다.

## 5. 주간 진척에서 열면 탭이 안 바뀐다

`?task=18-22` 만 주소에 얹는다. `tab` 은 안 건드린다 — **주간 진척에 머문
채로 창이 뜬다.** 닫으면 보던 자리 그대로다.

이것이 §1 에서 「보드에서 열기」와 갈리는 지점이다. 그 링크는 **남긴다** —
"이 덩어리를 보드에서 다루겠다"는 다른 뜻이고, 3단계에서 `role=` 까지 붙여
숫자가 맞게 해 뒀다.

## 6. 앞 단계에서 물린 것 — 이 단계에 해당하는 것

**① 로컬 state 를 없앨 때 그것에 기대던 것이 조용히 죽는다.** 2단계에서
「← 돌아가기」가 그럴 뻔했고 3단계 리팩터에서도 같은 위험이 있었다.
**이번이 가장 크다** — `patchTask` 사용처가 5곳, `busy` 가 7곳이다.
**하나라도 놓치면 그 자리만 조용히 안 돈다.**

**② 렌더 테스트가 없다.** `environment: 'node'` 라 화면 회귀는 자동으로 안
잡힌다. 빌드·테스트가 다 통과해도 **상태 단추가 안 먹는 것**을 못 잡는다.
브라우저 확인이 필수다.

**③ 확인 전에 낡은 dev 서버를 죽인다.** 3단계에서 낡은 서버가 500을 냈고
하마터면 "리팩터가 요구사항을 깨뜨렸다"고 보고할 뻔했다.

## 7. 안 하는 것

| | 왜 |
|---|---|
| **결정 대기에서 항목 열기** | 지금 **숫자만** 보여준다(「막힌 항목 5건」). 열려면 그 5건을 **먼저 목록으로 펼쳐야** 하는데, 그건 배선이 아니라 새 기능이다. 5단계 후보 |
| **간트에서 항목 열기** | 막대가 워크스트림이다. 항목 단위로 바꾸면 471줄짜리 간트가 되어 "언제 몰리나"를 못 본다. 지금의 막대 → 보드가 맞다 |
| 「보드에서 열기」 없애기 | 다른 뜻이다(§5) |
| `patchTask` 를 훅으로 빼기 | 페이지 안에 두면 된다. 지금 쓰는 곳이 페이지 하나다 |

## 8. 테스트

순수 함수로 뺄 것이 없다 — **이 단계는 배선을 옮기는 일이다.**
`lib/launchTaskLink.js` 의 `taskByCode` 는 이미 테스트가 있고 그대로 쓴다.

**회귀 확인은 기존 테스트가 한다.** 기준선 **77 파일 / 1200 테스트.**
`launchRouteGuard.test.js` 도 그대로 통과해야 한다(라우트를 안 건드린다).

**브라우저에서 볼 것 — 이 단계는 이게 검증의 전부다:**

| | |
|---|---|
| 보드의 상태 단추 넷 | 여전히 먹는가 (`patchTask` 5곳) |
| ⋯ → 해당없음 | 창이 뜨고 저장되는가 |
| 해당없음 보기 → 되돌리기 | 되는가 |
| 막힘으로 바꾸기 | `BlockDialog` 가 뜨고 결정에 걸리는가 |
| 여러 줄 골라 해당없음 | `bulkAction` 은 안 옮겼는데 멀쩡한가 |
| ＋ 항목 | 새 항목 창이 뜨는가 |
| 「나에게 맡기」 | 숫자가 그 자리에서 1 오르는가 |
| **주간 진척에서 줄 클릭** | **탭이 안 바뀌고** 창이 뜨는가 |
| 주간 진척에서 창 닫기 | 주간 진척에 그대로 있는가 |
| 「보드에서 열기」 | 여전히 보드로 가는가 |

## 9. 위험한 자리

**① `patchTask` 5곳 중 하나를 놓치는 것.** 옮긴 뒤 `grep -n "patchTask("` 가
`LaunchBoard` 에서 **0** 이어야 하고, 그 자리가 전부 `onPatch` 로 바뀌어야 한다.

**② `busy` 가 두 곳이 되는 것.** 페이지가 갖고 props 로 내린다. `LaunchBoard`
안에 `useState` 로 남으면 창의 `busy` 와 보드의 `busy` 가 갈린다.

**③ `TaskEditDialog` 의 「＋ 항목」.** `taskDialog` 는 `{mode:'create'}` 도
받는다 — 보드의 「＋ 항목」이 그것을 쓴다. 창만 옮기고 그 호출부를 안 고치면
새 항목 만들기가 죽는다.

**④ 3단계에서 만든 `{viewTask && !taskDialog && ...}` 조건.** 고치기 창이
열리면 보기 창을 숨기는 그 조건이 페이지로 같이 가야 한다.
