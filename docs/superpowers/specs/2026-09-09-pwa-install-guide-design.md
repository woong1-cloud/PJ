# PWA 2단계 — 설치 안내 자리

2026-09-09. 설치되는 것까지 배포한 뒤.

---

## 0. 무엇이 문제인가

**깔 수 있게 됐는데 깔 수 있다는 걸 아무도 모른다.** 지금 설치한 사람은
한 명이고, 그 사람은 자기가 만들었으니까 안다.

그리고 이건 다음 단계의 전제이기도 하다. **아이폰에서 푸시는 홈 화면에
깐 사람만 받는다.** 안내가 없으면 푸시를 만들어도 받는 사람이 없다.

## 1. 「끌 수 있어야 하지 않나」 — 만들 필요가 없다

맞는 걱정이다. 설치는 **한 번 하면 끝나는 일**이라, 이미 한 사람에게 계속
보이면 그때부터는 소음이다.

**그런데 새 끄기 장치를 만들 필요가 없다. 이 저장소에 이미 둘 다 있다.**

| | 어디 | 왜 끌 필요가 없나 |
|---|---|---|
| **상시 자리** | 계정 메뉴의 한 줄 | **메뉴를 열어야 보인다.** 안 열면 안 보이므로 끌 것이 없다 |
| **한 번 밀어주기** | `lib/newsItems.js` 의 `NEWS` 한 줄 | 읽으면 점이 사라진다. `news_seen_at` 이 **서버에** 남아 브라우저를 바꿔도 다시 안 뜬다 |

**소식이 정확히 이 일을 하라고 만들어진 것이다.** `NewsMenu.jsx` 의 주석이
그 판단을 이렇게 적어 뒀다 — 「벨은 나에게 온 것, 이 아이콘은 모아에 생긴
것이다.」 **"폰에 깔 수 있게 됐다"는 모아에 생긴 것이다.**

### 배너를 안 만드는 이유

화면 위에 띄우고 「다시 보지 않기」를 붙이는 방법도 있다. 안 한다.

- **끄기 상태를 어디에 둘지가 새 문제가 된다.** `localStorage` 는 브라우저를
  갈면 돌아온다. 서버에 두려면 컬럼이 하나 는다. 소식은 그 답을
  (`news_seen_at`) **이미 갖고 있다.**
- 배너는 화면 맨 위 한 줄을 영구히 요구한다. 한 번 하면 끝나는 일에
  그 자리를 내주는 값이 안 맞는다.
- `newsDismiss.js` 가 이미 배운 것이 있다 — **반사적으로 닫는 것과 읽는
  것은 다르다.** 배너를 새로 만들면 그 구분을 처음부터 다시 만들어야 한다.

### 소식 한 줄은 언제 빼나

**안 뺀다.** `NEWS` 는 날짜순 목록이고 새 항목이 위로 쌓인다. 시간이 지나면
`POPOVER_LIMIT`(3) 밖으로 밀려나 저절로 안 보인다. 도움말의 전체 목록에는
남는데, 그건 기록이라 남는 게 맞다.

## 2. 안내 화면 — `/install`

새 페이지 하나. **팝업이 아니라 페이지다** — QR 을 찍는 동안 열려 있어야
하고, 남에게 주소를 알려 줄 수도 있어야 한다.

담을 것:

| | |
|---|---|
| QR | 폰 카메라로 찍는다 |
| 주소 | `moa.noavibe.app` — 글자로도 있어야 한다. QR 이 안 찍히는 폰이 있다 |
| **아이폰 순서** | 사파리로 열기 → 공유 → 홈 화면에 추가 → **깐 앱에서 다시 로그인** |
| **안드로이드 순서** | 크롬으로 열기 → 「앱 설치」 또는 메뉴 → 앱 설치 |
| 왜 까나 | 한 줄. 「폰에서 바로 열리고, 다음 단계에서 알림을 받을 수 있습니다」 |

**아이폰의 「다시 로그인」을 반드시 적는다.** 홈 화면 앱은 사파리와 별개
저장소를 쓴다. 이걸 모르면 고장으로 읽고 거기서 멈춘다. **이 한 줄이
안내에서 제일 중요하다.**

### 이미 깐 앱에서 열면

`display-mode: standalone` 이면 안내 대신 「이미 설치된 앱에서 보고
있습니다」를 보인다. 깐 사람에게 설치 방법을 읽히지 않는다.

**다만 이건 "지금 이 창"만 안다.** PC 브라우저는 그 사람이 폰에 깔았는지
모른다. 그래서 계정 메뉴의 줄은 PC 에서 늘 보인다 — 그게 맞다. 이 페이지는
PC 에서 보라고 있는 것이다.

## 3. QR 은 정적 파일로 굽는다

**주소가 안 바뀐다.** `https://moa.noavibe.app` 하나뿐이다. 그러면 QR 은
매번 만들 것이 아니라 **아이콘과 똑같이 한 번 구워 커밋할 것**이다.

- `scripts/make-qr.mjs` → `public/icons/install-qr.png`
- 런타임 의존성이 없다. 화면은 `<img>` 하나다
- 굽는 데는 `qrcode` 가 필요하다. `npm i -D qrcode` 로 **devDependency 로**
  넣는다 — 결과물이 커밋되므로 빌드·런타임은 안 다친다

**아이콘 때 배운 것을 반복하지 않는다.** `public/icons/` 가 `.gitignore` 에
안 걸리는 것을 확인한다. 걸리면 배포본에만 QR 이 빠지고 로컬에서는 잘 된다.

## 4. 계정 메뉴의 한 줄

`components/TopBar.jsx` 의 계정 메뉴에 `MenuLink` 하나를 더한다.

```jsx
<MenuLink href="/install" onClick={closeMenu}>폰에 설치하기</MenuLink>
```

**어디에 두나.** 「브랜드 설정」·「도움말」이 있는 아래쪽 묶음이다. 이동
링크(요구사항·주간회의)와 섞지 않는다 — 그건 매일 쓰는 것이고 이건 한 번
쓰는 것이다.

**관리자만 보이게 하지 않는다.** 깔 사람은 전부다.

## 5. 미들웨어

`/install` 은 **로그인한 사람만** 본다. 지금 매처 그대로 두면 그렇게 된다.

로그인 전에도 보이게 할까 생각했는데 **안 한다.** 안 깔린 앱의 설치 안내를
로그인 전에 보여 줄 이유가 없고, `PUBLIC_PATHS` 를 늘리면 그만큼 열린
화면이 는다.

## 6. 앞 단계에서 물린 것 — 이번에 해당하는 것

**① `NEWS` 의 날짜가 열쇠다.** `newsItems.js` 주석이 적어 둔 그대로 —
새 항목은 **기존 어느 것보다 나중 날짜**여야 한다. 앞선 날짜로 끼우면 이미
본 사람에게는 영영 안 보인다. 지금 맨 위가 `2026-09-05` 다.

**② `POPOVER_LIMIT` 을 지키는 테스트가 있다.** 목록이 짧아지면 걸린다.
더하기만 하므로 안 걸리지만 알고 시작한다.

**③ 렌더 테스트가 없다.** `environment: 'node'` 다. `/install` 이 제대로
그려지는지는 눈으로 봐야 한다.

## 7. 테스트

순수 함수로 뺄 것이 적다. 그래도 둘은 못 박는다.

| | |
|---|---|
| `NEWS` 새 항목의 날짜 | 기존 최댓값보다 크다 (이미 있는 테스트가 잡는지 확인하고, 없으면 더한다) |
| `install-qr.png` | 파일이 실제로 있다. 매니페스트 아이콘 테스트와 같은 수법 |

**기준선 80 파일 / 1248 테스트.** 줄면 안 된다.

## 8. 브라우저에서 볼 것

| | |
|---|---|
| 계정 메뉴 | 「폰에 설치하기」가 보인다 |
| `/install` — PC | QR 이 뜨고 주소가 글자로도 있다 |
| QR 을 폰으로 찍기 | 모아가 열린다 |
| `/install` — 깐 앱에서 | 「이미 설치된 앱에서 보고 있습니다」 |
| 소식 | 점이 뜨고, 읽으면 사라지고, **다시 로그인해도 안 돌아온다** |
| 폰 화면 | `/install` 이 폰에서도 읽힌다 (안내를 폰에서 볼 수도 있다) |

## 9. 안 하는 것

| | 왜 |
|---|---|
| 화면 위 배너 | §1 — 끄기 상태를 새로 둘 자리가 필요해진다. 소식이 이미 한다 |
| 「앱 설치」 단추를 우리가 그리기 | `beforeinstallprompt` 는 크롬에만 있고 아이폰엔 없다. 반쪽짜리 단추는 안 되는 폰에서 더 헷갈린다 |
| 설치했는지 서버에 기록 | 알 방법이 없다. 폰의 홈 화면은 우리가 못 본다 |
| QR 을 런타임에 만들기 | 주소가 안 바뀐다. 정적 파일이면 의존성이 안 는다 |
| 로그인 전 공개 | §5 |
